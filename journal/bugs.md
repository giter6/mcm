# 缺陷日志

> 位置：`journal/bugs.md`　｜　只追加，不改写历史记录。
> 每次发现“结果不对 / 编译失败 / 合并出错”，先登记，再修。修复必须走 `fix/` 分支。

## 编号与状态

- 编号：`B001`、`B002`……全局递增，**不复用**；
- 状态：`待修复` → `修复中` → `已修复` → `已验证`（由非修复者验证）；无法修复记 `不修` 并写原因；
- 严重度：`致命`（结果错误/编译失败）、`高`（影响论文数字）、`中`、`低`。

## 修复流程

1. 在本文件登记一行（现象 + 严重度 + 出现在哪条分支）；
2. 从出问题的分支创建修复分支：`python tools/mcm.py new-fix --slug b001-xxx --base <分支>`；
3. 修复 + 重跑验证 + 更新 `journal/branches/` 日志（`mcm.py log`）；
4. 提交 PR 回合原分支（Squash）；**谁修的都先改状态为“已修复”**；
5. 另一位成员确认结果后改“已验证”；
6. 会影响论文数字的错误，必须在 `journal/team.md` 记录需要重跑哪几处。
